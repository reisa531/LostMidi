# 开发路线与验收范围

## 已实现

- 基础站点、公开 MIDI 与人物详情、来源及寻回记录展示、数据库迁移和 Docker Compose 部署。
- 统一后台、单管理员认证、MIDI 基本信息新增与编辑、会话撤销和版本冲突保护。
- 人物资料与历史昵称新增、编辑；作品署名的添加、角色调整与移除。保存立即公开，人物不是登录账号。

## 下一步：历史来源与寻回记录管理

沿用当前后台权限、Service / Repository 边界及事务和 revision 机制，为每件作品补充来源与寻回过程的管理表单。

1. 历史来源：网站名称、原始 URL、存档 URL、备注及可空时间。只记录有依据的信息，不虚构 Wayback capture。
2. 寻回记录：发生时间、寻回人、说明与关联资料；明确未知日期、无关联人物的表达方式。
3. 验收：创建、编辑、移除关联记录后公开详情同步；非法 URL、无效关联与并发提交不破坏已有记录；覆盖登录与过期会话、事务回滚和移动端表单。

之后再开展 MIDI 文件导入：先实现格式校验、SHA-256 去重、归属及权利检查、存储失败清理，再开放上传或下载。多用户贡献、审核、搜索与社区按实际需求推进。

## 本轮升级与验证

人物管理需要迁移 `003_person_revision.sql`。已有部署先备份并执行全部待应用迁移，再启动新版应用，见 [RUN.md](../RUN.md)。署名使用作品的 revision，人物使用自己的 revision；两个页面同时修改同一实体时只有一个旧版本提交能成功。

功能边界见 [Admin 文档](admin.md)，实际执行的验收结果见 [Implementation Report](implementation-report.md)。自动化写入检查只在专用测试库执行。
